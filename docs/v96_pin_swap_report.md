# `v96`（开启 LUT 引脚交换）9 用例全量实测与三方对比报告

> **结论摘要**：`v96`（`theia50per-ppt-hybrid-v96`）在 **`gpu02` 同 NUMA 双卡 `2 × Tesla V100`（`--gpus 2,3`）** 上完成了本机 Java CPU 基线中开启 `lutPinSwapping=true` 的全部 **`9 / 9` 非 `k_*` 竞赛用例**（总计 `9,167,537` 条间接连接）。  
> - **合法性**：`9 / 9` 全部一次性通过**进程内 64 分片 + 冷启动独立 JVM `F4BaselineDcpCheck`** 双重校验（`unroutedPins = 0`、`sharedPipNodes = 0`，回退次数 `fallbackAttempts = 0`）。  
> - **线长与 PIPs 收益**：9 用例总 Wirelength 从 `v94`（`swap=false`）的 `39,659,286` 直降至 **`27,354,497`（`-31.03%` / `-12.30M`）**；总 PIPs 从 `63,685,665` 降至 **`50,606,398`（`-20.54%` / `-13.08M`）**；逼近同口径纯串行 Java CPU（`25,580,815`，差距 `+6.93%`）。  
> - **运行时间与算力效率**：9 用例总 **`E2E = 1,909.96 s`**、**`Route design = 1,626.31 s`**，相对同口径 Java CPU（`E2E = 44,447.91 s`、`Route = 44,322.19 s`）实现 **`23.27×` E2E 加速 / `27.25×` Route 加速**；GPU Kernel 累计耗时反而比 `v94` **下降 `-20.64%`**（`394.13 s → 312.79 s`），总节点弹出数下降 **`-9.68%`**（`56.42B → 50.96B`）。

## 3. 核心现象分析（为什么线长和 GPU 算力都降了，部分大用例耗时却变长？）

1. **Multi-Target Goal Set 确实释放了巨大的线长与搜索空间红利**：
   - 9 个设计中约 **85.0%**（`7,788,967 / 9,167,537`）的连接拥有等价 LUT 交换候选（总共 `37,716,420` 个候选汇点，且全部满足 `max_dx = 0, max_dy = 0`）。
   - A\* 可以在同 Tile 的多个候选引脚中选择代价最低者：不仅总 WL 降 `-31.03%`、PIPs 降 `-20.54%`，**GPU 实际执行内核耗时累计仅 `312.79 s`**（比 `v94` `394.13 s` **更少 `-20.64%`**），总 `nodes_popped` 也下降 `-9.68%`；在拥塞缓解尤为明显的 `THEIA_20per` 上，轮数由 `50 / 66` 轮降至 `44` 轮，E2E 反超 `v94` **`-41.91 s`**（`306.04 s` vs `347.95 s`）。
2. **`THEIA`（`+179.8 s`）与 `THEIA_50per`（`+342.2 s`）E2E 增加的原因拆解**：
   - **收敛轮数拉长，长尾停留在 CPU**：`THEIA` 由 `30` 轮增至 `68` 轮（`+38` 轮），`THEIA_50per` 由 `56` 轮增至 `94` 轮（`+38` 轮）。当大量引脚改为非独占 `LOCAL_*` 后，同一批波内多个不同网的连接可能互相争夺热门引脚资源，虽有 `SINK_CLAIM_BIT` 同波互斥避免违法重叠，但末盘少量拥塞/高代价引脚在多轮往返协商中产生长尾。
   - **`LUTTools.swapMultipleLutPins` 串行后处理开销**：`F4_V66_POST lut=...` 在 `THEIA`、`THEIA_20per`、`THEIA_50per` 上分别耗时 `5.81 s`、`12.33 s`、`18.62 s`（9 用例累计 `40.72 s`）。
3. **竞态缺陷排查成果**：
   - 初次测 `THEIA_jpeg` 时暴露的 `Initial live nodes missing from the RRG manifest: 5` 根因已彻底解决（见 [pin_swap_gpu_plan.md](pin_swap_gpu_plan.md) 第 6.1 节：`RWRoute.categorizeNets()` 在 `lutPinSwapping=true` 时改为先 `awaitPreserve()` 再生成 `altSinkRnodes`）；随后 9/9 全量连续跑完零异常、零未映射节点。

## 4. 后续可优化方向（面向 `v97`）

1. **并行/提前局部收敛非独占汇点**：后期轮次（如 `iter >= 20`）对长期在少数候选引脚间震荡的局部连接收敛或锁定首选引脚，压缩 `THEIA` / `THEIA_50per` 的长尾轮次。
2. **多线程改造 `LUTTools.swapMultipleLutPins`**：按 Site / Slice 分片并行更新站内 LUT 映射，预计可将 `THEIA_50per` 的 `18.62 s` 降至 `2–3 s`。
3. **结合 `4 × V100` 全卡重测**：目前 `gpu02` 四张 V100 已恢复全空闲状态，后续可在 `4 × V100` 下验证更大算力配比对 `THEIA_50per` 的增益。
